# Screenshot fixtures (M0-12)

`claude-home/**` and `claude.json` are a synthetic `~/.claude` tree (home `/Users/fixture`) built
from `$SWIFT_REF/PoirotTests/Mocks/ScreenshotData.swift` (commit `a29dd6e`, 1738 lines) so that
Heimdall's real Rust loaders — not hand-built view props — produce the session/project/plan/history
data behind the Swift reference app's screenshot tests. Generated by a script kept out of the repo (ponytail: the
generator is a throwaway build tool, not a deliverable); regenerate by re-deriving it from
ScreenshotData.swift's source at the commit above if the tree needs to change.

Scope: `ScreenshotData.swift` only, per M0-12's Inputs. It has no todos, memory, MCP servers,
stats-cache, facets, file-history, debug logs, settings/hooks, commands, skills, output-styles or
plugins data (verified: `grep -inE "todo|memory|mcpserver|stats|facet|debug|plugin" ScreenshotData.swift`
only matches tool-call *content strings*, e.g. a Bash command mentioning `testMCPServerLoading`).
Full coverage of every on-disk format lives in `fixtures/synthetic/` (M0-11); this fixture set
exists only so the four screenshot-test projects, their sessions, plans, and history render
identically whether the Swift reference app builds the Swift objects in-process or Heimdall parses this tree.

## Fixed reference date and home

- **Reference date**: `2026-09-20T12:00:00Z`, standing in for ScreenshotData's
  `Date(timeIntervalSince1970: 1_771_598_200)` (`2026-02-20T14:30:00Z`, ScreenshotData.swift:10).
  Every `hoursAgo(h)` / `minutesAgo(m)` call (ScreenshotData.swift:11-12) is recomputed as an
  offset from the new reference date instead, so every timestamp in the tree is a fixed
  ISO-8601 value (`.000` milliseconds, `Z` suffix) with no dependency on the current date.
- **Home**: every `/Users/leo/...` path in ScreenshotData.swift (project paths, `Plan.fileURL`,
  Bash commands, `DerivedData` paths, `HistoryEntry.project`) is rewritten to `/Users/fixture/...`.
  Verified: `grep -rn "/Users/" claude-home claude.json | grep -v /Users/fixture` finds nothing.
- Project folders are encoded the same way `SessionLoader.swift:314-353`'s fallback and
  `docs/spec/claude-home-inventory.md`'s `<enc>` describe: every `/` in the (now `/Users/fixture`)
  path becomes `-`, e.g. `-Users-fixture-Dev-poirot`.

## Transcript record shape

Every `.jsonl` line is a `type: "user"` or `type: "assistant"` record matching
`docs/spec/claude-home-inventory.md` R2 / `TranscriptParser.swift:10-136,353-463`:
`uuid`, `parentUuid` (chains consecutive records), `isSidechain`, `sessionId`, `cwd`
(project path), `timestamp` (ISO-8601, `.000` fractional seconds), and `message.{role,content}`
(`message.id`, `message.model`, `message.usage.{input_tokens,output_tokens,
cache_read_input_tokens,cache_creation_input_tokens}` for assistant records). Content blocks are
`{"type":"text","text":...}`, `{"type":"thinking","thinking":...}`,
`{"type":"tool_use","id":...,"name":...,"input":{...}}`, and
`{"type":"tool_result","tool_use_id":...,"content":...,"is_error":...}` — one JSONL line per
Swift `Message`, its `content` array holding every block that message has (`TranscriptParser`
groups consecutive same-`message.id` assistant lines into one `Message`; since each mock `Message`
becomes exactly one line, there is nothing to group, and multi-block messages like `conv-001`'s
`m4` — text + `tool_use` in one turn — round-trip as one line with a two-element `content` array).

`uuid` values are `uuid5(fixed-namespace, "<sessionId>:<swift message id>")` — deterministic and
stable across regenerations, but not equal to the mock's short labels (`m1`, `tr1`, ...); see
below. `ToolUse.id` (`tu1`, `tu-grep`, ...) and `ToolResult.toolUseId` are copied through
unchanged, since `TranscriptParser.parseToolUseBlock` reads `block["id"]` directly
(`TranscriptParser.swift:406-420`).

## Not reproducible on disk

- **`successToast`, `errorToast`, `infoToast`** (1225-1248), the eleven **standalone `ToolUse`/
  `ToolResult` pairs** (1252-1458: `readTool`/`readResult`, `writeTool`/`writeResult`,
  `editTool`/`editResult`, `bashTool`/`bashResult`, `bashErrorTool`/`bashErrorResult`,
  `globTool`/`globResult`, `grepTool`/`grepResult`, `taskTool`/`taskResult`,
  `unknownTool`/`unknownResult`, `noOutputTool`/`noOutputResult`, `longContentTool`/
  `longContentResult`), and the **four diff-pair string sets** (1462-1534: `simpleDiffOld/New`,
  `multiLineDiffOld/New`, `addOnlyDiffOld/New`, `removeOnlyDiffOld/New`) are never loaded from
  `~/.claude` even in
  the Swift reference app — `ScreenshotTests_ToolBlocks.swift`/`ScreenshotTests_EditDiff.swift`/
  `ScreenshotTests_Standalone.swift` construct `ToolBlockView`/`DiffView`/`ToastView` directly from
  these values, bypassing `SessionLoader`/`TranscriptParser` entirely. Heimdall's Playwright/
  Vitest component tests for those same views are expected to do the same (pass props/TS fixture
  literals straight to the component), so there is nothing to place under `claude-home/`.
- **`emptySession`** (1213-1220): zero messages. `TranscriptParser.parse` requires
  `!messages.isEmpty` and `parseSummary` requires `userCount > 0 || !seenMsgIds.isEmpty`
  (`TranscriptParser.swift:44,114,327`) — an empty `.jsonl` (or one with only non-user/assistant
  records) can never become a `Session` through the real loader, so this factory has no on-disk
  form; Heimdall's loader is expected to skip such a file the same way.
- **`ToolResult.id`** (e.g. `tr1`, `tr-grep`, every standalone `*Result.id`): even inside the Swift reference app,
  `TranscriptParser.parseToolResultBlock` always assigns a fresh `UUID().uuidString`
  (`TranscriptParser.swift:427-432`) instead of reading an id from the file, so no on-disk value
  could reproduce it — this id is process-random in the Swift reference app itself.
- **`Message.id` for user turns** (`m1`, `m3-result`, `th1`, ...) and **assistant turns** (`m2`,
  `m3`, `t2`, ...): the real loader takes user ids from the record's `uuid` and assistant ids from
  `message.id` (`TranscriptParser.swift:83-94,98-108`), never from a mock's short label. The
  fixture's `uuid`/`message.id` values are fixed and reproducible (see "deterministic uuid" above,
  and assistant ids are `msg_<swift id>`) but are not textually equal to `m1`/`tr1`/etc.
- **`Session.totalTokens`** on every main session (`conversationSession`, `toolBlocksSession`,
  `thinkingSession`, `serverSession`, `taskToolSession`, `errorToolSession`, `editDiffSession`,
  `writeToolSession`, `longContentSession`): each mock sets an illustrative total larger than the
  literal sum of that session's own `TokenUsage.total` (`input + output`) values — e.g.
  `conversationSession.totalTokens` is `34200`, but its five assistant messages' usage sums to
  `13600`. `TranscriptParser.parse`/`parseSummary` always compute `totalTokens` as the sum of
  `usage.input_tokens + usage.output_tokens` over the session's own assistant records
  (`TranscriptParser.swift:121-124,317-323`), so Heimdall's loaded value is the true sum of this
  fixture's usage blocks (documented per-session in the generator's printed summary), not the
  mock's rounder illustrative number. (Sub-agent sessions are the exception: their token totals
  and turn counts *are* matched exactly, since their transcripts were authored from scratch —
  see below.)
- **`Session.model` for `migrationSession` (501-517) and `pipelineSession` (521-537)**: both set
  an explicit `model` even though their session has a single user message and no assistant reply.
  `TranscriptParser` derives `model` only from the first assistant message
  (`TranscriptParser.swift:95,119,255,303-305`); with no assistant turn, the loaded session's
  `model` is `nil`, not the mock's value.
- **Sub-agent transcript bodies**: `agentExplore1/2`, `agentPlan1`, `agentExplore3` all set
  `messages: []` in ScreenshotData (they are sidebar/card mocks only). Since an empty transcript
  is unloadable (see `emptySession` above), `subagents/agent-*.jsonl` were authored from scratch —
  alternating a `tool_use` and a `tool_result`-shaped `user` turn per turn, ending in a summary
  `text` block — sized so `userCount` (`TranscriptParser`'s stand-in for `cachedTurnCount`),
  the assistant `usage` sum (`totalTokens`), `model`, `startedAt` (earliest timestamp) and
  `endedAt` (latest timestamp) exactly match ScreenshotData's fields (verified: see the
  "Verification" section). The turn-by-turn tool names/inputs and the closing "Findings
  summarized for: …" text are invented, not sourced from ScreenshotData. `.meta.json`'s
  `agentType`/`description` are copied through unchanged (`SessionLoader.swift:296-301`).
- **`claude.json`**: no ScreenshotData factory defines `mcpServers` or per-project MCP config, so
  this is a minimal placeholder (`{"mcpServers": {}, "projects": {}}`) — present only so code that
  reads `~/.claude.json` against `HEIMDALL_CLAUDE_HOME` pointed at this tree doesn't error.
